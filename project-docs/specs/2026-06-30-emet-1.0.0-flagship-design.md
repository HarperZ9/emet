# EMET 1.0.0 Flagship Release — Design

- Date: 2026-06-30
- Status: APPROVED (operator approved the design; authorized push to GitHub + publish to PyPI on completion)
- Scope: bring EMET from `0.2.0-draft` to a frozen, production-grade `1.0.0` in
  parity with the other primary flagships (telos, index, forum, gather, crucible).
- Working tree: `c/dev/public/pubscan/emet` (canonical clone, origin
  `github.com/HarperZ9/emet`). The secondary clone `c/dev/state/emet` (local
  runtime artifacts) is left untouched and optionally re-synced from canonical at the end.

---

## 1. The honesty spine (load-bearing, non-negotiable)

EMET's only credential is re-derivation. Therefore `1.0.0` asserts **exactly two
things and nothing more**:

1. **The spec contract is frozen** — stable enough to build against.
2. **The reference implementations are production-grade.**

It does **not** claim re-derivability is "proven." SPEC §12's bar — an
*independent, different-author* implementation passing the vectors — stays
**explicitly open**. The fourth implementation added in this release (Go) is
written by the same operator, so it is **coverage, not proof**; the README's
"call for an independent implementation" stays prominent and the spec keeps
saying the bar is unmet.

Spec-freeze and external-validation are **orthogonal axes**. Conflating them
("we're 1.0, therefore re-derivability is proven") would be the exact in-band
overclaim EMET's `refuse` strips. The release holds that line.

The closed verdict lattice (`MATCH | DRIFT | UNVERIFIABLE`, plus the closed
auxiliary judgements) and the no-`TRUSTED`/no-authority invariant are **never
weakened** by any change here. `verdict.py`'s `governed()` guard remains the
structural enforcer and is extended, never relaxed.

## 2. Deliverables

Seven deliverables. Each ends on a green gate: `CONFORMANCE N/N` for every
implementation **plus** the full Python test suite (`pytest -q`) **plus**
`git diff --check`.

### D1 — Exit-code split (breaking, but free here)

No release was ever tagged (`git tag` is empty), so there is **no installed base
to migrate**. `1.0.0` ships the split as *the* scheme, collapsing the spec's
"v1.0 current / v1.1 target" two-step into one clean table:

| Exit | Meaning | Verdicts |
|---|---|---|
| `0` | clean | MATCH, COHERENT, CORROBORATED, INTACT, no markers, selftest ok |
| `1` | **a difference was found** | DRIFT, VIEW_DIFFERS_FROM_SOURCE, QUARANTINE_READ_PATH_DIVERGENCE, BROKEN |
| `2` | **UNVERIFIABLE** (could not check) | UNVERIFIABLE (any reason code) |
| `3` | markers detected | `refuse` with ≥1 marker |
| `64` | usage error | bad/missing arguments |

Rationale for the split line: exit `1` = a positive negative-finding (something
changed / diverged / a chain is broken); exit `2` = inability to check. `BROKEN`
is a *detection* of tampering, analogous to `DRIFT`, so it is exit `1`, not `2`.

**Vectors that change** (`expect_exit` 2 → 1): `verify-drift-single-byte`,
`coherence-injected-view-differs`, `audit-broken`, `audit-kind-tamper`. All
`UNVERIFIABLE` vectors stay at `2`. Marker vectors stay at `3`.

**Touches:** `membrane.py`, `organs.py`, `monitor.py`, all four impls,
`conformance/vectors.json`, every test asserting an exit code, `examples/demo.sh`,
`adapters/proof_surface_receipt.py` (records the code; values change, logic does not).

### D2 — Token rename `membrane_self_sha256=` → `emet_self_sha256=`

`selftest` emits **both** tokens during a deprecation window: the new canonical
`emet_self_sha256=<hex>` plus the legacy `membrane_self_sha256=<hex>` with a
one-line sunset note. SPEC §14 documents the window and the sunset version. The
JSON envelope uses the key `self_sha256`. Conformance vector `selftest-self-hash`
asserts `emet_self_sha256=`; a companion assertion keeps the legacy alias alive
for the window. All four impls emit both.

### D3 — JSON envelope (`--json`)

A normative, machine-readable output mode (SPEC §13's named "v1 target"),
emitted **in addition to** — never replacing — the human tokens, selected by a
global `--json` flag.

- The envelope **is `canonical_json`**: a single JSON object, keys sorted,
  `", "` / `": "` separators, `ensure_ascii=True`, UTF-8. This reuses the exact
  byte-form §7 already pins for the audit chain.
- Because the form is pinned, the envelope is required to be **byte-identical
  across all four implementations** — a strictly stronger re-derivability
  property than the human tokens. Conformance vectors assert substrings of the
  serialized JSON (e.g. `"verdict": "DRIFT"`), so the runner needs **no JSON
  parser**.
- Envelope schema (pinned in SPEC §13):
  ```json
  {
    "command": "<verify|coherence|refuse|corroborate|audit|selftest|anchor>",
    "corpus_sha256": "<hex>",            // marker commands only
    "corpus_version": <int>,             // marker commands only
    "emet_version": "1.0.0",
    "exit_code": <int>,
    "reason": "<E_*>",                   // UNVERIFIABLE only
    "results": [ {"path": "...", "verdict": "MATCH", "got": "...", "want": "..."} ],
    "self_sha256": "<hex>",              // selftest only
    "spec_version": "1.0.0",
    "subject": "<path or [paths]>",
    "verdict": "<closed-lattice token>"
  }
  ```
  (Per-command field presence is pinned in the spec; the `governed()` guard
  applies to every `verdict`/result token, so no authority word can enter an
  envelope.)
- Closed-lattice invariant: a test asserts `"TRUSTED"` (and the rest of
  `FORBIDDEN`) never appears in any serialized envelope.

### D4 — Fourth implementation: Go

- `impl/go/emet.go`, standard-library only (`crypto/sha256`, `encoding/json`,
  `os`, `os/exec`, `bufio`). A trivial `go.mod` with **zero dependencies**.
  Compiles to a binary; the conformance runner already runs binaries directly
  (and its docstring explicitly anticipates "a Rust or Go build").
- Written **spec-first** from `SPEC.md` + `vectors.json` + `markers.corpus`. Any
  ambiguity it surfaces is recorded in a new `docs/spec-findings-from-go-impl.md`
  (the same differential-oracle discipline that produced F1 from the Node impl).
  Framed honestly as same-author coverage, not the independent-author bar.
- New CI job mirroring the Rust/Node jobs.

### D5 — Spec freeze (`0.2.0-draft` → `1.0.0`)

Resolve the pre-freeze punch-list from `docs/spec-findings-from-js-impl.md`:

- **F2** — tighten the `coherence` / `corroborate` vectors' `expect_substr` to
  include `result=` so the normative §13 grammar is actually tested.
- **F3** — pin the `.refused` replacement token (`[REFUSED-IN-BAND-AUTHORITY]`),
  the `<file>.refused` filename convention, and the overlapping-match rule in §4.
- **F4** — state the audit **prev-linkage** check explicitly in §7 (each stored
  `prev` equals the prior entry's chain), so an independent impl cannot legally
  omit it.
- **F5** — pin "UTF-8 encode the concatenation before SHA-256" in §7.
- **F6** — pin `anchor`'s contract (exit 0 + chained log entry, no required
  stdout token) and pin `selftest`'s failure exit (the UNVERIFIABLE / exit-2 class).
- **F7** — by design; record that the asymmetry is intentional.

Then: fold the D1 exit table, D2 token rename, and D3 envelope into the normative
text; bump `spec_version` to `1.0.0` in **all** locations (`SPEC.md`,
`README.md`, `SECURITY.md`, `USAGE.md`, `COVERAGE.json`, `conformance/vectors.json`,
`adapters/attest.py`, `adapters/proof_surface_receipt.py`, plus the JSON envelope
constant); change Status `DRAFT` → `STABLE/FROZEN`; update §12 + README to "four
implementations, independent-author bar still open."

### D6 — Packaging + unified `emet` CLI

Highest-churn, highest-risk piece (it touches the proven core), so it is a
discrete, checklisted phase **guarded by the full vector suite**.

- Move the five core modules into an `emet/` package with package-relative
  imports (`from . import corpus`); add `emet/cli.py` (a flat dispatcher:
  `emet anchor|verify|coherence|refuse|corroborate|audit|selftest` → membrane;
  `emet watch|observe|confirm|gate` → organs; `emet monitor report|reanchor` →
  monitor) and `emet/__main__.py`.
- **Back-compat + conformance-path stability via thin root shims.**
  `membrane.py`, `organs.py`, `monitor.py` at the repo root become 2–3 line
  shims (`from emet.membrane import main; main()`), so `python membrane.py …`
  and `python conformance/run.py membrane.py` keep working **byte-compatibly at
  the command line**. The run-from-checkout, zero-install story is fully preserved.
- **Artifact-of-record.** `selftest` now hashes the **sorted concatenation of
  the package core source files** (`emet/membrane.py`, `corpus.py`, `verdict.py`,
  `organs.py`, `monitor.py`) — a stronger, honest self-identity for a
  multi-file implementation. §14 updated to pin the file list and order.
  (`selftest` is per-impl self-identity, never cross-impl compared, so a
  multi-file Python hash and a single-binary Go hash coexist correctly.)
- `pyproject.toml`: distribution name **`emet`**, import package `emet`,
  console script **`emet`**, **zero runtime dependencies**, MPL-2.0, Python
  `>=3.8`. Optional `[attest]` extra for the in-toto adapter only.
- Tests updated to import from the package; conformance unchanged.

### D7 — Flagship polish + release

- Version + badges in README (`0.2.0-draft` → `1.0.0`, CI badge intact, add a
  PyPI badge), CHANGELOG `1.0.0` entry, COVERAGE.json `spec_version`.
- Refresh the forward-delivery regression test and run the
  `public-surface-sweeper` delivery gate.
- Refresh `examples/demo.sh` for the new exit codes + a `--json` example.
- `RELEASE-CHECKLIST.md` capturing the tag → push → GitHub release → PyPI
  publish steps.
- Cut an annotated `v1.0.0` tag.
- **Publish (operator-authorized):** push `main` + the tag to
  `github.com/HarperZ9/emet`, cut the GitHub release, and `twine upload` the
  built sdist+wheel to PyPI as `emet`. Verify the published artifacts
  re-derive (download, `pip install`, `emet selftest`, conformance).

## 3. Execution strategy (ultracode)

Coherence-critical, multi-file-interdependent edits (the Python reference, the
spec text, `vectors.json`, the packaging restructure) are done in the **main
loop** with careful edits and committed per phase. Parallelizable and
verification-heavy work is **orchestrated with workflows**:

- **Discovery sweep** — parallel read-only agents produce a precise edit-site
  inventory (every `exit()` site + its verdict class, every token/version
  occurrence, the Rust/Node impl structure) before any shared-file edit.
- **Multi-language port** — once the Python reference + vectors are committed,
  fan out one agent per language (Rust, Node, Go). They touch **disjoint files**,
  so they run against the committed base without worktree isolation; each must
  reach `CONFORMANCE N/N`. The main loop integrates and re-verifies.
- **Adversarial verification** — after the freeze, multiple skeptic lenses
  (closed-lattice / no-overclaim / re-derivability / spec-vs-code drift) attempt
  to refute the release before the tag is cut.

Commit between phases (non-isolated workflow agents share the tree and can
revert uncommitted work). Never weaken an invariant to make a check pass.

## 4. Risks and decisions

- **Packaging touches the proven core.** Mitigation: root shims keep the
  conformance command line identical; the vector suite is the guardrail (if all
  vectors still pass post-restructure, behavior is preserved). If de-risking is
  preferred, D6 can ship as a `1.1` follow-up — but the operator chose PyPI, so
  it is in `1.0.0`.
- **Exit-code split is genuinely breaking** for anything keying on exit `2`.
  Accepted because nothing is released. (No known downstream shells out to emet
  on exit `2`; if telos/proof-surface do, they update with the release.)
- **`--json` flag vs the runner's path-joining.** `conformance/run.py` treats
  any non-subcommand `run` arg as a path; it needs a one-line change to pass
  through args starting with `-`.
- **Go toolchain in CI** — add `actions/setup-go`; local builds use the system
  `go` if present, else the impl is documented as CI-verified.

## 5. Success criteria

- All four implementations pass the full (expanded) `conformance/vectors.json`.
- `pytest -q` green; `python membrane.py selftest` and `emet selftest` agree.
- `pip install` of the built wheel exposes a working `emet` console script that
  passes conformance.
- `SPEC.md` is `1.0.0` / STABLE with F2–F6 resolved; no file > 300 lines, no
  function > 50 lines; closed lattice intact (a test proves no `FORBIDDEN` token
  can be emitted, including in JSON).
- README/SPEC state the version honestly and keep the independent-impl bar open.
- Pushed to GitHub (`main` + `v1.0.0` tag + release) and published to PyPI
  (`emet`), with the published artifacts re-derived.

## 6. Discovery refinements (verified) + final execution plan

A read-only discovery sweep (4 agents, every impl run empirically) produced an
exhaustive edit-site inventory. Baseline confirmed green: Python conformance
19/19, Rust + Node 19/19, full pytest suite passing, Python 3.12.10 / Node
v25.2.1 / rustc 1.92.0 / Go 1.23.4 (portable). It surfaced decisions below.

### 6.1 Uniform exit table (supersedes the §5 sketch)

Semantic, tool-wide: `0` the checked property HELD · `1` a NEGATIVE FINDING was
produced · `2` the property COULD NOT BE CHECKED · `3` markers · `64` usage.

- exit `1`: DRIFT, VIEW_DIFFERS_FROM_SOURCE, QUARANTINE_READ_PATH_DIVERGENCE,
  BROKEN, organs DRIFTED/NEW/GONE, organs NOT_REVERTIBLE, monitor baseline CHANGED.
- exit `2`: every UNVERIFIABLE (any reason code).
- **`verify` precedence** (a single call can mix classes): exit `1` if ANY target
  is a difference, else `2` if ANY is UNVERIFIABLE, else `0`. Pinned in §5.
- organs/monitor exits adopt the same semantic but remain Python-core tooling
  (governed by SPEC + their tests, never the cross-language vectors).
- Adapters (`adapters/*.py`) are out-of-core: they exit `0` on successful emit
  (verdict carried inside the JSON), `64` on usage — unchanged.

### 6.2 Cross-impl divergences to fix at the freeze (not enshrine)

Discovery found the human stdout is NOT byte-identical across impls (all pass
only because §13 is a substring contract). The freeze fixes the genuine defects:

- **Rust §9 violations:** Rust emits PROSE reasons (`(no anchor)`, `(unreadable)`,
  bare `result=UNVERIFIABLE`). §9 requires a stable machine reason code. Fix Rust
  to emit `reason=E_*`.
- **`anchor` on an unreadable path:** Python/JS → `UNVERIFIABLE` exit 2; **Rust
  silently exits 0**. Pin `UNVERIFIABLE`+exit 2 in §4, fix Rust, add a vector.
- **Reason-code enum (standardized across impls):** `E_NOT_FOUND` (no such path),
  `E_NO_RAW_CHANNEL` (exists, unreadable), `E_NO_ANCHOR`, `E_NO_CORPUS`,
  `E_NO_CORPUS_VERSION`, `E_NO_SECOND_READ_PATH`, `E_LOG_CORRUPT`. JS currently
  collapses file errors to `E_NO_RAW_CHANNEL` → distinguish `E_NOT_FOUND`.
- **`audit` no-log:** Python/Rust print `no log` (no `chain=` token); JS prints
  `chain=INTACT`. Normalize Python/Rust to `chain=INTACT log_entries=0` (genesis,
  trivially intact) so §13's `chain=` line always appears.
- **`refuse` (F3):** pin the `.refused` replacement token
  `[REFUSED-IN-BAND-AUTHORITY]` (corpus.py already uses it; JS uses `[REFUSED]` →
  align) and the `<file>.refused` filename + non-overlapping leftmost replacement.

The `--json` envelope pins the GOVERNED fields (command, verdict, subject,
exit_code, reason, corpus_version/sha, self_sha256, emet_version, spec_version)
identically across impls; impl-flavored detail (verify want/got, corroborate
per-channel hashes — explicitly impl-defined per §4/§15) may differ or be omitted.
Conformance asserts governed substrings (e.g. `"verdict": "DRIFT"`,
`"exit_code": 1`). Human stdout line-order/extras stay as each impl has them.

### 6.3 Packaging trap-list (P5 must handle)

- **HIGH severity — `corpus.py` default path:** `corpus_path()` =
  `dirname(__file__)/conformance/markers.corpus`. Moving the file into `emet/`
  silently resolves to the nonexistent `emet/conformance/...` → `E_NO_CORPUS`
  whenever `EMET_CORPUS` is unset. Only `test_corpus.py::
  test_shipped_corpus_loads_at_version_1` (pops the env) catches it. Fix the path
  math to `dirname(dirname(__file__))/conformance`. Do NOT duplicate the corpus
  (one file, pinned sha `aec90a7b…`).
- **Root shims are load-bearing.** A package file with `from . import corpus`
  cannot run as a bare script; the tool fed to `conformance/run.py` must be the
  root shim. Shims at root (`membrane.py`/`organs.py`/`monitor.py`/`corpus.py`/
  `verdict.py`) keep every subprocess-by-path consumer working unedited:
  `test_membrane/monitor/organs.py`, `conformance/run.py`, `adapters/*.py`,
  `examples/demo.sh`, both `docs/**/render.py`, and the CI workflow.
- `test_corpus.py` does flat `import corpus` + `importlib.reload`; the root
  `corpus.py` shim must be a real reloadable module (or repoint the test to
  `emet.corpus`).
- **Transcript regeneration:** `test_walkthrough.py` asserts byte-equality of
  `docs/rationale/walkthrough/transcript.txt`. The token rename + selftest-basis
  change WILL change emitted bytes → regenerate the committed transcript via its
  `render.py` after P2/P5. `docs/rationale/witness-walkthrough/render.py` is a
  committed, non-CI harness that also touches root paths — verify it too.
- selftest identity value changes by design (package core-file set, §14).

### 6.4 Final phase order (each ends green; commit per phase)

- **P1 — Python reference behavior:** exit split + reason-code standardization +
  `anchor`-unreadable + `audit` no-log normalization, with matching SPEC §4/§5/§9
  edits + `vectors.json` exit changes + Python tests. Gate: pytest + Python
  conformance.
- **P2 — Python reference surface:** token rename (emit both) + `--json` envelope
  (membrane 7 cmds; organs/monitor too, Python-only) + SPEC §13/§14 + new `--json`
  & selftest-token vectors + `run.py` `--json` passthrough + closed-lattice-in-JSON
  test. Gate: pytest + Python conformance.
- **P3 — Multi-language port (workflow, parallel, disjoint files):** edit Rust,
  edit JS, write Go from SPEC alone (record findings in
  `docs/spec-findings-from-go-impl.md`). Gate: ALL FOUR impls conformance N/N.
- **P4 — Spec freeze finalization:** F2/F4/F5/F6 prose + F7 note; version bump to
  `1.0.0` across all sites; Status DRAFT→STABLE; §12 + README "4 impls, bar open";
  COVERAGE.json, SECURITY.md, Cargo.toml, CHANGELOG `1.0.0`. Gate: forward-delivery
  + pytest + all conformance.
- **P5 — Packaging + unified CLI:** `emet/` package + root shims + `cli.py` +
  `__main__.py` + `pyproject.toml` (`emet`, console `emet`, zero deps) +
  corpus path fix + selftest package-core basis + test updates + regenerate
  transcript. Gate: editable install → `emet selftest` + all conformance (via
  shims) + pytest + transcript byte-match.
- **P6 — Flagship polish:** README badges/version + PyPI badge, demo.sh (new exits
  + `--json`), doc cross-links, `RELEASE-CHECKLIST.md`, public-surface-sweeper +
  forward-delivery refresh. Gate: sweeper + forward-delivery + full pytest + all
  conformance.
- **P7 — Adversarial verification (workflow):** closed-lattice / no-overclaim /
  re-derivability / spec-vs-code-drift skeptics try to refute the release; fix
  findings; re-verify.
- **P8 — Release (authorized):** merge `release/v1.0.0` → `main`, tag `v1.0.0`,
  push `main`+tag, GitHub release, build sdist+wheel, `twine upload` to PyPI
  (`emet`), then re-derive the published artifacts (`pip install`,
  `emet selftest`, conformance).
